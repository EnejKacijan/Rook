# Flexible Week availability correctness and UX — 2026-09-06

## Findings and correction

1. **Reproduced root cause:** with today Sunday Sep 6, five upcoming Mon/Tue/Wed/Fri/Sat sessions and Sun/Mon/Tue/Wed availability, the old domain returned `{ status: 'conflict', error: 'No schedule changes are needed.' }`. It used the end of the calendar week (Sep 6) to collect remaining sessions, despite displaying a rolling seven-day window through Sep 12. The target set was empty. Separately, the UI rendered expansion/skip actions for every error, including that false no-change result.
2. **Domain/UI fix:** availability requests identify `windowDays: 7 | 14`. Target discovery includes unstarted effective occurrences in the rolling window and existing recent missed/persisted obligations; calendar-week rollover no longer excludes the visible upcoming workouts. Whole-window targets, rather than only changed rows, appear in the review. Every Review action transitions to a dedicated result/review sheet state.
3. **Explicit result model:** `ready` means a meaningful changed proposal, `no-change` means all remaining dates already fit, `insufficient-capacity` includes remaining/selected/usable day counts, and `conflict` represents invalid input, stale-plan references or other constraints. The UI renders exactly one branch. Other Flexible Week actions retain their existing contracts.
4. **Selected dates:** only supplied dates are allowed in this UI path. Hidden-window, past, malformed or beyond-horizon dates are rejected. Unselected Fri/Sat sessions must move to selected dates, or the proposal cannot be applied. Active/completed sessions remain immutable; occupied dates reduce usable capacity. The existing legacy explicit carry algorithm and 14-day bound are not redesigned or invoked implicitly. After expansion, both visible weeks are constrained: the second week's own remaining sessions are included, not silently left on unavailable days.
5. **Profile baseline:** initialize the seven visible dates from `profile.availableDays`, excluding locked active/completed dates. Valid Mon–Sun selects seven; a narrower profile selects matching weekdays only. Missing/invalid availability deterministically selects none. This is mount-time UI state only and never writes the profile. Review is disabled while selection equals the baseline, enables after a difference and disables again if reverted. Additional dates are initially unselected.
6. **Tile context:** each effective workout date shows its name as quiet secondary text. Two-line truncation handles long names without widening the grid; date stays primary. No icons or new colors. Context does not change what selection means. Both helper lines are left aligned. Existing sheet scaffold, buttons, date selection language, back/X, drag handle and Today entry remain unchanged.
7. **No-change:** separate “Your schedule fits” state with “Your current schedule already fits these days.” Only Edit Days and Done; no skip, expansion, apply button or fake diff.
8. **Capacity:** separate “More training days needed” state, e.g. “5 sessions remain, but you selected 4 training days.” Offers Show More Dates when not yet expanded, lower-emphasis explicit skip, Edit Days and Done. Invalid/conflict gets its own explanation without capacity-only links. Nothing is written at review time.
9. **Expansion:** Show More Dates returns to the picker and reveals the grouped FOLLOWING 7 DAYS section, preserving first-week selections. The wording accurately describes a rolling interval even midweek. Select enough usable dates, then Review produces ORIGINAL/ADJUSTED dates for every affected-window session, including clearly marked unchanged rows. Applying remains explicit and stale guarded.
