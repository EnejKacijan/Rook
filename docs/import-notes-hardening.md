# Import Plan from Notes — hardening report

Date: 2026-09-06. Scope: existing notes importer, not a new importer or global redesign.

## Implementation and semantics

1. **Previous pipeline:** expanded note lines → regex/context parser → source verification → `normalizeGeneratedProgram` → shared PlanEditor. A failed local finalize could fall through to full-note AI import. Applying published React state before its persistence effect and cleared an active workout.
2. **Hardened pipeline:** the same parser/finalizer is used with explicit review mode. Production requests local parsing, transient source diagnostics and field review; final acceptance constructs a validated independent state, writes it, then publishes it. The legacy service default remains for compatibility; the production import caller explicitly selects review mode and does not invoke its AI fallback.
3. **Normalization:** existing bullets, whitespace, CRLF, Unicode multiplication/dashes, table and semicolon handling are retained. Added source line/character offsets, Slovenian short weekdays, written `to` ranges and context-safe heading detection.
4. **Days:** named calendar days are preserved. Ordered unnamed workouts retain source order and require calendar assignment. Duplicate weekdays remain separate candidates and must be resolved. Explicit recovery sections cannot reopen an implicit Monday workout.
5. **Matching:** existing canonical/normalized/synonym matching and unresolved identity review remain authoritative. Shared editor resolves saved aliases and existing custom exercises; low-confidence names are not promoted into canonical matches by this pass. No new fuzzy matcher was added.
6. **Review model:** normalized candidate plus transient issues (`NEEDS_REVIEW`) and classified source records. Existing identity match status remains separate. The final CTA requires both source-field review and identity resolution. No percentages are shown.
7. **Sets/reps/load:** working prescriptions, decimal-comma kg/lb and per-exercise source-scoped weights are retained. Historical-looking per-set notation and implicit rounds require prescription review. Missing units and negative/assistance loads require explicit review rather than assuming a positive load.
8. **RIR/RPE:** explicit supported RIR is preserved. Bare `@number` without clear units/RIR is reviewed. RPE conversion is visible and reviewed, not silently accepted. Unsupported RIR values can be corrected or left unspecified.
9. **Supersets:** complete adjacent equal-round A1/A2-style pairs and clear two-exercise named Superset/SS groups use existing superset IDs. Unequal/incomplete/ambiguous groups remain reviewable; the existing pairing and reorder controls are now available during import review. Slash alternatives are not automatically paired.
10. **Warm-ups:** existing general preparation stays separate. An exercise name followed by warm-up lines and a Working section no longer loses the working exercise. Unlabelled numeric ramps are surfaced for review, not interpreted as dozens of general warm-up sets or substituted for working weight.
11. **Advanced sets:** explicit appended/numbered/final AMRAP uses existing set types. Drop/rest-pause/failure instructions receive a choice of existing set and method, or an explicit note-only choice. Segments are not invented or counted as independent normal sets. Failure uses existing RIR=0, not another failure type.
12. **Per-side:** an explicit instruction offers the existing `normal`/`per_side` logging choice; it does not force every unilateral exercise into double entry.
13. **Custom exercises/aliases:** reused existing mapping, creation and Remember this match flow. No duplicate custom library or alias storage. Creating a library record remains an explicit separate action; cancelling the plan does not necessarily remove that library record.
14. **Unclassified text:** meaningful unclassified, recovery and unsupported warm-up excerpts are surfaced. Adjacent related lines are grouped to avoid one confirmation per line. Safe structural metadata/comments are classified separately. Users explicitly acknowledge unrepresented text instead of it disappearing silently.
15. **Multiple weeks:** multiple explicit Week/Teden numbers, including Markdown/emoji headings, are rejected with a one-week/manual-review explanation. This importer does not flatten a block into one invented week.
16. **Restrictions/equipment:** conflicts are visible without automatic exercise removal/replacement. Imported restrictions remain in the profile; existing fail-closed start checks remain responsible for preventing an unsafe start. Default-gym incompatibilities are listed for review.
17. **Apply/persistence:** active workouts and optional active sessions block acceptance. Validation checks existing structural invariants. A failed storage write leaves the old state intact and keeps a visible retry error beside the final action. A ref prevents double submission. Temporary Today/occurrence overrides are cleared on permanent replacement; existing Flexible Week fingerprint/quarantine semantics remain in force.
18. **Plan History/Training Block:** acceptance normalizes the existing block model and appends one Imported plan version. Parse/review steps do not create versions. Previous versions and completed sessions are retained.
19. **Backup/reload:** actual ZIP backup/restore test preserves imported program, block and version. Source diagnostics/raw draft are not durable. Reload before acceptance returns to the existing plan; reload after acceptance retains the import.

## Evidence

20. **Curated corpus:** 20 named A–T fixtures, plus 40 deterministic formatting variants.
21. **Adversarial corpus:** 30 additional synthetic human-style snippets, each also pasted through the runtime UI.
22. **Runtime outcomes:** 50 different notes: 13 confident, 32 correctly requiring review, 5 unsupported. This is not an artificial success-rate target. Examples of semantic defects found and fixed or made explicit: phantom recovery workout; lost exercise mistaken for a heading; merged duplicate days; invented weekday placement; hidden effort ambiguity; lost grouping/AMRAP; warm-up/working-load association; truncated written ranges; Markdown multieweek flattening. A false-positive RIR warning introduced during hardening was caught by the corpus and corrected.
23. **Remaining boundaries:** this is not a history importer, multi-week importer or medical interpretation engine. Unlabelled detailed ramps, vague compound-set instructions and ambiguous alternatives may still need explicit manual review. No claim of universal parsing accuracy: no known high-severity silent semantic misparse remains in the asserted synthetic corpus. Physical-device-only behavior is unverified.
