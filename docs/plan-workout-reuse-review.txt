ROOK — Reuse workouts from the active plan, 23 October 2026

Decision
The existing SavedWorkouts owner now provides Choose a workout. From your plan
is a live projection of accepted state.program.days; Saved workouts contains
independent user-created snapshots. No automatic copies, migration or quota
consumption occurs when a plan is built, changed or viewed.

Entry points
Today uses Choose a workout. More options offers it next to Start freestyle
workout; rest-day Train anyway has the same two choices. Profile > Workouts
opens the same picker. Add to Up Next continues showing saved workouts only.
Search covers both groups. Create workout is a secondary 44px action beside
the Saved workouts heading, including an empty saved library.

Plan preview and commands
A plan workout shows its exercises and targets. Start extra workout explicitly
states that it will not mark a scheduled workout as complete. It uses the
existing freestyle session and reusable-instance factories, including safety,
equipment checks and the usual logger/history. The session is detached from
scheduled occurrence IDs, and completing it does not advance the plan/block.
The active logger retains Extra workout after reload/Resume and uses Plan
targets for the prescriptions copied at the initial action. Actual saved
workouts added afterwards retain their own Saved workout label.

Save a copy uses the ordinary template draft/name/editor/writer flow. It focuses
the name field and explains that the copy is saved separately. Copies remain
independent after plan edits/replacement. The normal saved-workout access policy
remains the owner of explicit saves; no new billing provider was connected.
Only the accepted active plan is exposed, never generated or locked drafts.

Correctness
The reference binds profile ID, plan ID/version, day ID and a content signature.
Start and final Save recheck inside the durable command. Changed or removed
sources require a new review, without matching another workout by its name.
Duplicate names are distinguished by weekday and, when needed, plan position.
Starts and saves have intent IDs, and storage failure cannot publish a session.
Fresh exercise/set/segment/superset IDs isolate actual execution from targets.
The existing saved-template sanitization preserves supported custom, timed,
per-side, superset and segment prescriptions without carrying completion data.
