Implementation:
- Extracted the existing logger carry behavior into workoutWeightChanges.js.
  It advances through one contiguous group of equal old loads or blank defaults.
- Stops at a different load, manual load entry, pending raw load edit, completed
  or advanced set, or partially completed side. Editing a logged source only
  corrects that source. Counts, effort, history and prescription stay unchanged.
- History adoption has weightEntryMode=history; actual manual entries have
  mode=manual and explicit provenance. Old manual/history records from the
  previous Use implementation remain compatible. Same-valued manual re-entry
  now persists intent instead of being discarded as a numeric no-op.
- Native bodyweight history null remains distinguishable from an unknown blank.
  Existing unit conversion and absolute assistance amounts remain intact.
- One durable write publishes the load edit and its carry. Failed writes leave
  saved state unchanged and the next step can be retried safely.
- When other sets change, a brief Updated N sets / Undo message appears. Undo
  restores only owned load/provenance fields, preserving unrelated later work.
  Subsequent load edits, completion, navigation or session changes expire it.
