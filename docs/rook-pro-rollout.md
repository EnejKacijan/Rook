# ROOK Pro rollout checklist

The Free/Pro UI and access paths are implemented behind an **off-by-default** switch. Do not enable either rollout flag until a real sandbox purchase and restoration have been verified on the deployed PWA. The client flag is presentation only; the server independently checks Firebase ID tokens, RevenueCat `rook_pro`, and the server rollout flag before allowing paid Coach generation.

Keep RevenueCat Web Billing with one `rook_pro` entitlement, the existing `monthly` (`P1M`) and `annual` (`P1Y`) packages, and the intended €5.99/month and €39.99/year storefront prices. Annual alone is expected to have a seven-day free trial. Monthly must have none. This UX pass does not modify the dashboard, product IDs, prices, periods or eligibility settings. Set `VITE_ROOK_REVENUECAT_PUBLIC_KEY`, the server-only `ROOK_REVENUECAT_SECRET_KEY`, and real `VITE_ROOK_PRIVACY_URL` / `VITE_ROOK_TERMS_URL`. Keep the secret key and `ROOK_FIREBASE_SERVICE_ACCOUNT_JSON` in Netlify server environment variables only. The service account must belong to Firebase project `rook-1d2c8` and be able to use Auth Admin and Firestore. Do not commit its JSON.

The paywall reads RevenueCat's customer-specific `getOfferings()` packages. Only an Annual `defaultSubscriptionOption.trial` with a free seven-day phase produces trial claims. Missing or ineligible offers use the paid Annual CTA. The numeric base prices supply the monthly equivalent and savings badge; neither is an independent billing price. Offers are refreshed and compared before checkout so changed prices or eligibility require another review. Web Billing eligibility is controlled by the configured RevenueCat billing account policy; this PWA has no native StoreKit integration, so it must not claim to verify an Apple subscription-group trial. See [RevenueCat Web Billing eligibility](https://www.revenuecat.com/docs/web/web-billing/product-setup).

Opening ROOK, signing in, generating the first personal plan, and opening/selecting a paywall never start a trial. The first personal generated plan is Free; another activation is gated using the current plan and canonical plan history. Contextual paywalls retain the attempted action. Purchase completion resumes it only after active SDK entitlement and independent server verification for the same account. Restore refreshes that same entitlement without buying or automatically repeating an abandoned action.

Turning off renewal does not remove Pro while the billing entitlement is active. Confirmed expiry returns access to Free, preserves the activated plan and all user content, and never runs a local trial timer. Over-limit Saved Workouts remain visible, usable and editable; only new creation is gated. Premium appearance falls back to Standard without overwriting its stored preference, and returns with Pro. Coach retains conversation history and the remaining lifetime Free allowance.

The disposable local review is `/scripts/rook-pro-review.html` on Vite port 4198. It imports the real paywall with example packages and no billing callbacks. Its `Local review · Example prices · No payment` label belongs only to that development entry, which is excluded from the production build.

The server stores Coach usage in `rookCoachUsage/{firebaseUid}` and request reservations below it. It stores counters, hashed question identity, request status and timing, not Coach text or workout contents. These paths are not client-writable under the existing Firestore rules. Pro checks use the same Firebase UID as the RevenueCat Web SDK; anonymous-to-Google account linking retains that UID. A fully anonymous user who erases all site/Auth data cannot recover the old UID, so the lifetime Free Coach allowance cannot be recovered or enforced against that reinstall without a durable linked account.

A provider reply alone does not consume a Free response. The app saves a usable final answer locally, then acknowledges the request idempotently. If delivery or acknowledgement fails after provider success, the reserved slot remains held for its ten-minute lease so the same message can be retried; it does not become lifetime usage merely because the provider ran. Client acknowledgement cannot prove that a human saw the answer, so the separate daily provider-attempt cap remains essential against deliberately abandoned replies. Exercise the interrupted-response and retry path against the real backend before rollout.

The Free response allowance never resets. Separately, the backend limits Pro to two simultaneous generations, 30 request starts per minute and 500 per day, and caps Free provider attempts at 30 per day to bound repeated failed or canceled model calls. Those are temporary abuse ceilings, not a recurring Free allowance or a marketed Pro message quota. Revisit them with real cost and usage data before rollout.

Set `ROOK_PRO_PRODUCTS_READY=true` only after both products, entitlement, legal links and purchase/restore paths are verified. Enable `ROOK_PRO_ROLLOUT=true` and `VITE_ROOK_PRO_ROLLOUT=true` together only after owner approval. Then verify Free, purchase, cancellation, pending approval, restore, expiry, account change, multi-device identity, the three-response Free Coach allowance, Annual trial eligibility, and physical-iPhone safe-area/keyboard behavior. Keep the switches false if any of those checks fail. Existing plans, templates, history, backup and sync remain available regardless of subscription state.
