# ROOK Account & Sync setup for owner review

The local implementation targets Firebase project `rook-1d2c8`. On 2026-09-28 only the Firestore rules were deployed to that project. The ROOK web app, Hosting, Functions, Storage, and Netlify were not deployed by this task.

Backend verification (2026-09-28): Firebase CLI authentication can access this project and its default `eur3` Firestore database. Anonymous and Google Auth are enabled; `rook-training.netlify.app` and `localhost` are authorized. The released `cloud.firestore` ruleset matches the local `firestore.rules`. An isolated real-service test confirmed first anonymous sync, exact-ID cloud recovery, owner-only access, an offline queue and reconnect, and tombstone reconciliation. A real Google account link and physical-iPhone popup/recovery remain to be tested before web rollout.

1. Copy the registered **Web app** config values into local `.env` as `VITE_ROOK_FIREBASE_API_KEY`, `VITE_ROOK_FIREBASE_AUTH_DOMAIN`, `VITE_ROOK_FIREBASE_PROJECT_ID`, `VITE_ROOK_FIREBASE_STORAGE_BUCKET`, `VITE_ROOK_FIREBASE_MESSAGING_SENDER_ID`, and `VITE_ROOK_FIREBASE_APP_ID`. The first, second, third, and sixth fields are required by the current Auth/Firestore client; Storage and sender ID are retained centrally when supplied, but ROOK does not initialize Storage or Analytics. The project ID must be `rook-1d2c8`. These are public client configuration values, not service-account credentials. Restart Vite after changing them.
2. Keep **Google** enabled in Firebase Authentication → Sign-in method and keep the actual app origin (including `rook-training.netlify.app`) in Authentication → Authorized domains. Local Vite origins used for testing must remain authorized too.
3. `firestore.rules` is deployed to `rook-1d2c8` and matches the released ruleset. The rules are scoped to authenticated UID paths and deny physical document deletion. For future reviewed changes, run emulator tests before deploying only rules with `npx firebase deploy --only firestore:rules --project rook-1d2c8`.
4. Complete a real Google link, fresh-device Google restore, sign-out/return, and wrong-account rejection using a dedicated test Google identity before putting production data on this path. Physical iPhone Safari/PWA Google popup behavior must be checked: redirect-based sign-in on Netlify requires additional same-origin auth-helper setup for browsers that block third-party storage.
5. Only after the release gate, set the same public Web config and `VITE_ROOK_ACCOUNT_SYNC_ROLLOUT=true` in the Netlify production build environment and deploy the application. Until then, the account implementation remains dormant even if public Firebase config is present. Continue exporting local ROOK backups until actual cloud acknowledgements are observed.

Workout photos and Coach conversations stay on the device in this version. A Google credential already tied to a different ROOK account is an unresolved conflict, never an automatic merge. Tombstones remain in Firestore indefinitely until a separately reviewed retention/compaction policy exists.
